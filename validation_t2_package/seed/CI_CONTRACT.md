# Copilot implementation contract: T1/T2 CI evaluation

Use the assigned workspace and the PDF's four stages. Read REQUIREMENTS.md and case.json. The source application, BasePage, conftest.py, case.json, REQUIREMENTS.md and pytest.ini are immutable; the root CI job compares them to its pre-agent snapshot. Do not edit training_ci or inspect fault-switch implementations to derive expected values. The app already runs at BASE_URL (default http://127.0.0.1:8765) during agent work. The external grader starts its own servers after that server is stopped.

Implement in pages/settings_page.py and tests/test_settings.py; preserve existing methods. Add only these required POM methods for T1: `choose_auth(value)` selects none/password and waits for observable readiness; `reload()` refreshes the actual browser and waits for the loaded form. Existing `open`, `choose_connection`, `fill`, `save` and BasePage waits must remain usable. Keep requirement assertions in tests. No fixed sleeps, skipped/xfail placeholders, fake DOM, HTTP-based UI assertions, application edits or expectations derived from actual output.

T1 tests: at least four executed pytest cases, with names containing `connection_visibility`, `auth_visibility`, and `save_reload`. Parameterize save/reload across Serial and TCP so both modes run; include the assigned case values. Assert both directions of connection visibility and None/Password visibility, exact persisted active values and authentication after actual reload. The independent grader also calls the learner POM against actual Chrome using separate TCP and Serial values, testing password and None persistence; assertions come from the independent requirements.

T2 tests: at least eight executed cases, including names containing `save_reload`, `port_boundary`, and `invalid_save`. Parameterize `port_boundary` over 1, 65535, 0, 65536 and non-integer text; assert acceptance or rejection independently. Parameterize save/reload over two distinct TCP configurations and assert changed values survive an actual reload. `invalid_save` must establish a valid saved baseline, attempt invalid data, then reload and prove the baseline was not overwritten. Keep the same cases on every server variant; do not skip or change expectations based on the variant. The correct app must pass. The no-persist app must fail a `save_reload` assertion; bad-boundary must fail a `port_boundary` assertion. Startup errors, unrelated Selenium errors and crashes do not count as detection.

For code mode, implement `automation/guardrails.py --workspace PATH --junit PATH` as readable deterministic orchestration. It runs `sys.executable -m pytest tests -q -ra --junitxml=JUNIT_PATH` with cwd set to the resolved workspace argument. Inherit BASE_URL unchanged: the evaluator owns the server. Preserve the pytest exit status and output, create the JUnit destination's parent if needed, and never overwrite tests, expected values or application files. This helper must use subprocess argument lists, a finite timeout, and distinguish infrastructure failure from assertion failure in its human-readable output. Do not fabricate a JUnit report. MD-only mode does not require or invoke automation helpers, but requires the same real tests and POM behavior.

Keep the common workflow/evidence files from the handbook. For fresh transfer, use the supplied workflow (and only the permitted general helpers in code mode); create current-case tests afresh. Do not copy finished demo tests or POM implementations when the CI task explicitly forbids them.

T2 code mode additionally requires `automation/evaluate_variants.py --workspace PATH`. This is the handbook's server-owning serial evaluation runner. Start and stop only your own subprocess servers for correct, no-persist and bad-boundary, each on a free loopback port with clean owned state. Poll readiness, pass that server's BASE_URL to guardrails.py with a distinct JUnit path, preserve logs and parse the real results. Correct must pass; both mutants must fail relevant assertions, with no skips or setup errors. A timeout, occupied port, failed startup or unrelated failure is blocked/failed, never a detection. Stop each owned child in a finally block; never kill the process occupying another port. During Stage 1 the root owns port 8765: use separate free ports when exploring variants, and do not terminate the root server.

The variant runner exits 0 only after all three expected outcomes and writes fresh `evidence/variant-evaluation.json` with `status: "passed"` and a `variants` mapping. Each variant entry has `pytest_returncode` (correct: 0; no-persist: 1; bad-boundary: 1), plus its actual JUnit/log paths and useful counts. On failed/blocked evaluation write the real status and exit nonzero. The external grader invokes this entrypoint after its own servers are stopped, then independently checks the learner suite on all variants; the runner's JSON is not the sole oracle. MD-only does not require either automation entrypoint.

## External evaluation commands

Prerequisites: Python 3.12; `python -m pip install -r training_kit/test_team/scaffold/requirements.txt`; actual Chrome/Chromium plus matching driver, or working Selenium Manager downloads. On the GitHub-hosted Ubuntu runner use its installed Chrome/driver, exporting CHROME_BINARY and CHROMEDRIVER when discovery requires it. No sandbox-disabling flags are required. Stop the agent-stage server before invoking:

```bash
python training_ci/grade_test.py --lab t1 --workspace work/t1-demo --mode code
python training_ci/grade_test.py --lab t2 --workspace work/t2-transfer-md --mode md-only
```

The grader serially owns servers on ephemeral loopback ports and passes BASE_URL to pytest. It runs the selected learner suite directly, checks JUnit (no skips/errors; required relevant assertion failures), and in code mode checks guardrails.py against the correct server too. T2 code mode also executes the server-owning evaluate_variants.py contract after those servers stop. It records logs/JUnit and grade.json under workspace/evidence/ci, plus a screenshot on a T1 semantic failure after browser creation. Exit 0 means the measured contract passed; any other exit means failed or blocked. Node 22 and Copilot CLI belong to the caller's agent setup; the grader itself requires no agent authentication. Classroom grading is not adversarial isolation.
